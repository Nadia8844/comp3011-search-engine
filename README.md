# COMP3011 Search Engine Tool

A command-line search engine that crawls [quotes.toscrape.com](https://quotes.toscrape.com/), builds an inverted index, and lets you search it interactively with TF-IDF ranking and exact phrase search.

## Architecture Overview

```
comp3011-search-engine/
├── src/
│   ├── crawler.py     — BFS web crawler with politeness window and logging
│   ├── indexer.py     — Inverted index with frequency and position tracking
│   ├── search.py      — TF-IDF ranking, AND search, and phrase search
│   └── main.py        — Interactive CLI shell
├── tests/
│   ├── test_crawler.py
│   ├── test_indexer.py
│   └── test_search.py
├── data/
│   └── index.json     — Compiled inverted index (generated by build)
├── requirements.txt
└── README.md
```

## Project Overview

The tool is split into four modules:

- `crawler.py` — crawls all pages of the target site using breadth-first search, respecting a mandatory 6-second politeness window and logging all activity to `search_engine.log`
- `indexer.py` — tokenises page text and builds an inverted index storing word frequency and token positions for each page
- `search.py` — implements `print`, `find` (AND search), and `find "phrase"` (exact phrase search) with TF-IDF ranking
- `main.py` — provides the interactive command-line shell with a `help` command

## Usage

Start the shell from inside the `src/` directory:

```bash
cd src
python main.py
```

### Commands

**build** — crawl the site and save the index to disk:
```
> build
```

**load** — load a previously built index:
```
> load
```

**print** — show the full index entry for a word, including frequency and token positions:
```
> print nonsense
```

**find** — AND search, returns all pages containing every query term, ranked by TF-IDF score:
```
> find indifference
> find good friends
```

**find (phrase mode)** — exact phrase search using stored positional data:
```
> find "good friends"
```

**help** — display all available commands:
```
> help
```

**exit** — quit the shell:
```
> exit
```

## Testing

Run the full test suite from the project root:

```bash
pytest -v
```

Run with coverage report:

```bash
pytest --cov=src --cov-report=term-missing
```

The test suite has 53 tests with 100% coverage across crawler, indexer and search modules.

### Test Strategy

Tests are organised into three files mirroring the source modules:

- **test_crawler.py** — tests crawler initialisation, URL validation, domain filtering, link extraction, fragment stripping, and the full crawl loop. All HTTP requests are mocked using `unittest.mock` so no real network calls are made during testing. Also tests the politeness window is called with the correct delay and that duplicate URLs in the queue are skipped.
- **test_indexer.py** — tests tokenisation edge cases (empty strings, numbers, mixed case), index building correctness, frequency and position recording, save/load round-trips, missing file handling, and that positions survive a full serialisation round-trip.
- **test_search.py** — tests single and multi-word AND queries, phrase search with consecutive and non-consecutive positions, TF-IDF scoring, ranking order, case insensitivity, empty queries, and the edge case where query words exist in the index but on non-overlapping pages with no intersection.

## Design Decisions

**Crawler** uses breadth-first search to discover pages layer by layer from the seed URL. BFS was chosen over DFS because it visits the most directly reachable pages first, giving the index better coverage of core content before deeper tag and author pages. URLs are validated against the seed domain and deduplicated using a visited set to prevent revisiting. Script, style and meta tags are stripped before text extraction to avoid indexing JavaScript or CSS as content. All network errors are caught gracefully and logged as warnings rather than crashing the crawl.

**Inverted Index** stores word frequency and token positions for each page. Positions are recorded as zero-based indices in the tokenised word list. This dual storage enables both TF-IDF relevance ranking and exact phrase matching without requiring a separate data structure for each.

**TF-IDF Ranking** weights words that appear frequently in a page but rarely across the collection, giving more meaningful results than raw term counts. The `find` command intersects posting lists for all query terms — only pages containing every word are returned — then ranks results by combined TF-IDF score, highest first.

**Phrase Search** uses the stored positional data to verify that query words appear at consecutive token indices within the same page. Wrapping a query in quotes triggers phrase mode: `find "good friends"` returns only pages where those two words appear literally side by side in the tokenised text. This is a stricter and more precise match than AND search.

**Storage** uses plain JSON for human readability and portability. The index can be inspected in any text editor, is safe to load without arbitrary code execution risks, and works across Python versions without compatibility concerns.

**Logging** uses Python's standard `logging` module rather than print statements. Crawl progress and network errors are written to `search_engine.log` in the project root, keeping the terminal output clean while preserving a full audit trail of the crawl.
